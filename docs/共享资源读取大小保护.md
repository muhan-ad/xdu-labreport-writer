# 共享资源读取大小保护

版本：0.105.0。0.104.0 的共享资源检查对每个响应直接使用 `arrayBuffer()`，异常文件超出清单声明时可能在页面内分配过大的缓冲。现在使用响应流逐段读取：清单最多 2 MiB；单个文件以清单声明大小为上限，且清单限制单文件不超过 32 MiB。超过上限即停止读取并报告不一致；响应流不可用时明确报告无法安全读取，不将其标记完整。文件仍逐个校验 SHA-256。

这是页面侧的读取保护，并不证明整机或 iOS 原生层的内存峰值受到同样限制。当前 Capacitor iOS 本地资源处理代码对普通文件会先在原生层读取数据；其实际 iOS WebKit 行为及内存仍须在苹果设备上验证。[WebKit 的 Fetch 说明](https://webkit.org/blog/7521/a-few-words-on-fetching-bytes/)介绍了响应流读取；不能将该资料当作本应用的 iOS 设备验收。

新增单元测试覆盖超长文件和清单提前停止、无响应流安全失败；完整测试 388 项通过。实际构建的 93 个共享资源在桌面浏览器模拟 iOS 平台及安卓 WebView 中检查通过；缺失文件、取消和重试回归通过。安卓原生检查仍核对 131 个安装资源。安卓安装前后 217 个文件一致；测试后 216 个与安装前一致，另一个为系统 WebView 设置。

iOS 工程已同步并核对资源清单；没有 Xcode 构建或苹果设备测试。iOS 在线数据更新仍未接入：当前只读请求对应清单返回 404，不能以此推断将来已发布文件的跨域配置；本地签名包导入不受此判断影响。
