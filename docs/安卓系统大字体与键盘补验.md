# Android 系统字体 200% 与键盘补验（0.74.0）

本轮没有修改正式应用功能或版本。此前的大字体证据来自桌面 Chromium 内的样式放大；本次改为当前 Android 模拟器的真实 system font_scale=2.0。

先比较真实 100%／200% 系统字号，首页标题的计算字号由 22px 变成 44px，文字范围高度约 25.9px 变为 51.4px，表明应用已响应系统字号，不需要另外强制修改 WebView 字体。没有注入内联字体放大样式，也没有减小用户所选字号或停用动效。

## 页面与按钮

独立验收包内，13 个正式页面／弹窗在五种窗口共 65 组通过：320×568、320×320、568×320、768×1024、1024×768。每组同时确认 Android 放大后的 body 字号仍为 30px，避免窗口模拟把系统字号还原后造成假通过。

覆盖首页、学生信息、设置、帮助、队列、章节管理、AI 历史、测量、AI 配置、实验操作菜单和报告的生成／图表／AI 页。检查横向溢出、弹窗边界、页脚、按钮文字及滚动后的实际命中位置，报告生成按钮无需先滚动页脚。没有执行生成、真实模型或学校操作。

320×320 的极小窗口中，长实验名使用已有的可滚动标题区，截图未完整显示第二行不等于文字丢失；额外逐字检查了五种窗口标题在滚动时的可见范围，全部字符均能读全，关闭按钮仍通过命中检查。小窗口需要滚动，并非声称所有标题能同时完整展示。已查看极小窗口配置／报告与实际横屏键盘截图。

这些窗口由原生 Android WebView 的调试接口模拟；字体来自真实系统设置，不是实体五种手机／平板或其他厂商字体的验收。

## 实际输入法

Gboard 与 Android 原生点击／文字事件在 200% 字号下通过四项：科学计数法 12.5e-3 与切换正负、下一项保留键盘、实际竖横屏输入可见、保存后完整重载恢复 -12.5e-3。

竖屏键盘展开后可用 412×574 CSS 像素，横屏 866×168。实际输入框均位于可见区域且在工具栏上方；横屏输入框约 y=1.68～71.71，工具栏约 y=83.42～168，无横向溢出。不是通过模拟键盘高度来代替原生输入法。
