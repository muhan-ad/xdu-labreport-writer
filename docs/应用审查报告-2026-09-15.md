## 一、总体结论

**应用已具备实用的报告生成能力，但在扩大分发前，建议先补齐更新信任链、桌面权限边界和科学计算校验。**

优势是工作流完整、实验数据结构化、报告生成与 AI 润色分离，已有用户数据隔离、资源更新回滚、取消任务和回归测试。真实 Word 测试也验证了原生公式生成和独立 Word 实例保护。

主要缺点集中在三个方面：

1. **安全防线不完整**：远程实验包可以更新可执行脚本，缺少发布签名验证；页面拥有过宽的文件接口；预览 HTML 未净化；密钥可明文存储并通过 HTTP 发送。
2. **部分功能与宣传存在差距**：正常 DOCX 预览分支实际上无法运行；仓库云函数拒绝意见反馈路径；静态检查通过不能证明计算和报告内容正确。
3. **长期维护成本偏高**：主进程和前端文件过大，资源与用户文件混合备份，依赖清单不一致，缺少统一输入校验与发布验证入口。

不使用主观百分制打分。本报告将问题按影响、触发条件和证据排序。

### 优先级说明

- **P1：高优先级**——建议在扩大公开分发前解决，涉及本机权限、密钥、云资源滥用或核心科学结果。
- **P2：中优先级**——建议在接下来的维护版本解决，涉及功能缺陷、可靠性、性能或测试保障。
- **已复现**：通过本地隔离执行或真实测试验证；**代码确认**：根据实际执行路径确认；**部署待核实**：代码存在风险，但没有访问生产配置验证实际暴露程度。

## 四、安全问题详情

### S01 · 热更新实际具有代码发布能力

**位置**：[下载入口](E:/agent-project/labreport-writer/main.js:945)、[合并更新包](E:/agent-project/labreport-writer/main.js:1067)、[应用更新包](E:/agent-project/labreport-writer/main.js:1117)、[运行 Python](E:/agent-project/labreport-writer/main.js:1545)。

更新包中的 `common` 会整体替换，其他文件也会进入用户实验目录，包括 `generate.py` 和公共 Python 模块。之后生成报告会执行这些代码。当前没有验证包的发布签名、已认证摘要、实验文件清单或最低兼容应用版本；应用阶段的版本号由页面传入。

**影响及前提**：若更新源、发布账号或相关页面执行环境被控制，恶意脚本可在用户下一次生成时以该用户权限执行。正常界面仍需用户确认更新，这不是“无需操作即可远程攻击”的证明。HTTPS 保护传输，但不能替代发布者身份验证；当前本地资源指纹也不是远程包的数字签名。

**建议**：将含脚本的包视为软件发布。客户端内置验签公钥，对规范化清单签名，清单绑定版本、文件摘要、大小和兼容条件；主进程独立验证下载与应用的关联。纯数据包与可执行代码更新分开，拒绝未列入清单的文件。

**验收**：篡改任一文件、伪造版本、错误签名、缺失签名、过旧版本或不兼容包均不得提交；原有数据和可用版本保持完整。

### S02 · 文件接口突破了报告目录边界

**位置**：[读取文件](E:/agent-project/labreport-writer/main.js:841)、[打开文件](E:/agent-project/labreport-writer/main.js:1436)、[预加载 API](E:/agent-project/labreport-writer/preload.js:4)。

`read-docx-buffer` 只检查文件存在，直接把任意路径内容以 Base64 返回；不验证扩展名、报告归属或大小。`open-file` 同样接受任意已有路径。多处 IPC 忽略 `event`，没有检查 `senderFrame` 和主窗口身份。

**复现**：给读取接口传入实验根外的项目 `package.json`，并附带不可信来源的模拟事件，返回 `ok: true` 且内容完整一致；打开接口也将这个路径交给了模拟的系统打开函数。

**影响及前提**：攻击者先获得页面脚本执行能力后，可进一步读取当前用户可读文件，或调用系统处理其他类型文件；不是单靠远程知道文件名就能访问该接口。

**建议**：页面传报告 ID，由主进程解析路径；统一校验调用窗口和顶层 frame、真实路径、目录归属、扩展名、大小。拒绝链接/目录联接越界。系统打开操作只接受明确允许的报告类型，并等待 `shell.openPath` 返回结果。

**验收**：实验根外 JSON、可执行文件、链接跳转路径、未知 frame 和非主窗口调用全部被拒绝，正常生成报告仍可预览和打开。

### S03 · 文档预览缺少隔离与 HTML 净化

**位置**：[Mammoth 转换](E:/agent-project/labreport-writer/main.js:830)、[HTML 降级预览](E:/agent-project/labreport-writer/src/renderer.js:1631)、[页面头部](E:/agent-project/labreport-writer/src/index.html:3)、[窗口配置](E:/agent-project/labreport-writer/main.js:147)。

转换得到的 HTML 直接进入主页面 `innerHTML`；未发现 CSP、导航拦截或新窗口限制。隔离构造的 DOCX 超链接经转换后仍保留 `javascript:` 协议。Mammoth 官方也明确说明输出不做安全净化。[Mammoth 安全说明](https://github.com/mwilliamson/mammoth.js#security)

**影响及前提**：恶意或被替换的报告进入预览、用户点击恶意链接等条件成立时，可能在拥有 `labAPI` 的页面中执行脚本，再与 S02 组合扩大影响。本次没有执行完整 XSS 或本机攻击链。

**建议**：优先把文档展示放入无预加载桥的隔离视图；对转换 HTML 使用维护中的净化器并限制 URL 协议；设置 CSP；阻止主窗口离开本地应用页面，默认拒绝弹窗和不需要的权限。只取文本的 `getReportText` 可改用纯文本提取接口。

当前 `contextIsolation: true`、`nodeIntegration: false` 是正确配置；**不能因为没显式写 `sandbox: true` 就断言沙箱关闭**。导航和 IPC 边界仍需补齐。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

### S04 · 密钥存储与传输保护不足

**位置**：[保存设置](E:/agent-project/labreport-writer/src/renderer.js:152)、[设置写入密钥](E:/agent-project/labreport-writer/src/renderer.js:2622)、[AI 请求](E:/agent-project/labreport-writer/main.js:1696)。

API Key 与普通设置一起写入 `localStorage`，页面脚本可读。主进程没有要求 `apiUrl` 为 HTTPS，实际隔离验证中 `http://example.invalid/v1` 收到了带假 Key 的请求参数，与 README 的“仅经 HTTPS 发送”不一致。

**建议**：在主进程使用系统支持的加密存储（如 Electron `safeStorage`），页面仅接触“已配置”状态和密钥 ID；默认强制 HTTPS。若要支持本机模型，设计独立的、范围明确的本地端点模式，避免普通云服务 Key 被误送至 HTTP。提供清除密钥和迁移旧配置功能。

**验收**：普通页面不能取回已存 Key；HTTP 云端地址保存或请求时被拒绝；端点切换显示实际接收方。加密存储不能防御已完全控制当前操作系统账户的攻击者，应准确说明边界。

### S05 · 匿名签发上传凭证存在滥用风险

**位置**：[云函数](E:/agent-project/labreport-writer/cloud/contribute-credentials/index.js:57)、[签名字段](E:/agent-project/labreport-writer/cloud/contribute-credentials/index.js:34)、[客户端大小上限](E:/agent-project/labreport-writer/main.js:1400)。

函数允许请求者选择符合格式的 key，只限制单次 1–20 个文件，并提供 600 秒有效的 PUT URL；代码没有身份、对象归属、速率、累计容量或内容大小约束。客户端的 20MB 限制不约束直接调用云函数/COS 的请求者。知道其他对象 key 的人还可能请求同 key 的覆盖凭证，取决于桶策略。

**影响及前提**：若按仓库“免鉴权”部署且没有外部控制，可被用于重复签发、大对象写入、垃圾投稿和内容覆盖。**未读取生产网关、桶策略，不能认定线上没有防护或已经产生损失。** 密钥不下发是优点，但不代表签发接口不存在风险。

**建议**：服务端生成不可预测的投稿 ID 和对象名；限定凭证用途及数量，增加来源限流、单次/累计配额、服务端大小约束、隔离审核区和过期清理。验证 CAM 最小权限与禁止覆盖策略。不要把固定“客户端秘密”作为唯一鉴权方案。

**验收**：超额、超大、越权 key、重复覆盖请求被拒绝；投稿失败能清理或过期回收已上传的部分文件。

### S06 · 公网 URL 检查不能覆盖所有实际连接

**位置**：[主机判断](E:/agent-project/labreport-writer/main.js:1179)、[DNS 检查与重定向](E:/agent-project/labreport-writer/main.js:1210)。

`isBlockedHost` 将地址按冒号截断：`fc00::1`、`fe80::1` 被错误判为非阻止地址，IPv6 回环 `::1` 则碰巧被阻止。`httpsGetJson` 跟随重定向时未重新验证目标，没有跳转次数上限；预检查 DNS 与实际请求解析分离。

**影响及前提**：受控端点或重定向可绕开“仅公网”的设计意图；实际是否能访问目标仍取决于网络连通性、TLS 等。本次没有向内网发请求。相对重定向还可能直接失败，属于兼容性问题。

**建议**：使用可靠的 IP/CIDR 分类，统一处理 IPv4、IPv6、映射地址；每跳重新验证 URL，以当前 URL 解析相对地址，限制次数，并在实际连接解析阶段执行同一限制。更新与投稿端点尽量使用明确的 HTTPS 域名允许列表。

## 五、正确性与功能缺陷

### C01 · 体积不确定度没有处理共同厚度

**位置**：[体积不确定度合成](E:/agent-project/labreport-writer/物理实验/实验脚本/长度与体积的测量/generate.py:126)。

代码令 `V = Vp - Vh - Vs`，三个体积共用同一次厚度测量 `d`，却使用 `sqrt(uVp² + uVh² + uVs²)`，把三个派生体积当作互不相关量。

在其余原始输入相互独立的假设下，应从整体模型 `V = (L·W - πD²/4 - x·y)·d` 求偏导，厚度贡献应为 `(L·W - πD²/4 - x·y)²·u(d)²`。共享测量量产生的相关性不能在派生量合成时直接忽略。[NIST 不确定度合成说明](https://physics.nist.gov/cuu/Uncertainty/combination.html)

**复现**：沿用当前示例数据及现有各输入不确定度，原程序 `uV = 17.6968986878 mm³`，按整体模型得 `17.6429188340 mm³`，相对高约 **0.306%**。此数值仅隔离共同厚度这一差异，不表示其他误差模型已全部核准；在其他几何比例下差异可能更大。

**建议/验收**：修正为基于原始测量量的传播公式，并同步报告中的公式和措辞；增加厚度误差占主导、孔/槽比例变化、极小剩余体积等已知答案测试。

### F01 · 正常 DOCX 预览分支永远跳过

**位置**：[加载脚本](E:/agent-project/labreport-writer/src/index.html:875)、[库导出](E:/agent-project/labreport-writer/src/docx-preview.min.js:7)、[预览调用](E:/agent-project/labreport-writer/src/renderer.js:1612)。

捆绑库导出 `window.docx`，调用侧却检查 `window.docxPreview`；页面也没有加载该浏览器构建依赖的 `JSZip`。隔离运行确认 `docx.renderAsync` 存在，而 `docxPreview`、`JSZip` 均为 `undefined`。

**后果**：当前正常渲染分支被跳过，进入 Mammoth 降级模式，损失公式和版式。这不是仅仅“某些 Word 公式不兼容”。

**建议/验收**：统一库导出和调用，显式打包依赖；用真实报告验证正文、表格、图片及公式的预览结果，确保正常文件不走降级分支；保留明确标注局限的回退模式。与 S03 一起修复。

### F02 · 仓库中的意见反馈服务不可联通

**位置**：[反馈 key](E:/agent-project/labreport-writer/src/renderer.js:2136)、[客户端允许路径](E:/agent-project/labreport-writer/main.js:1335)、[云端正则](E:/agent-project/labreport-writer/cloud/contribute-credentials/index.js:16)。

前端发送 `contributions/feedbacks/<时间戳>/feedback.json`，主进程允许；云函数只允许 `variants|reports`。本地调用函数返回 HTTP 400，合法报告路径作为对照返回 200。

**建议/验收**：统一请求协议，增加 variants/reports/feedbacks 的正反向契约测试，再同步部署；生产函数若已另行修改，仍应回写仓库，防止重新部署回退。

### F03 · 输入“是数字”不等于实验数据有效

**位置**：[前端检查](E:/agent-project/labreport-writer/src/renderer.js:911)、[保存入口](E:/agent-project/labreport-writer/main.js:399)、[静态验证器](E:/agent-project/labreport-writer/validate_schema.py:35)、[计算入口](E:/agent-project/labreport-writer/物理实验/实验脚本/长度与体积的测量/generate.py:84)。

前端主要检查必填项；主进程保存不按 schema 验证；公共 `load_data` 只读取 JSON。各实验自行检查，规则不一致。现有静态验证器检查类型与维度，但缺少大于零、仪器误差非负、配对读数约束、分母非零及几何可行性等规则。

**复现**：将示例板长 `L` 在内存中改为 0，schema 验证仍通过，调用 `_compute` 出现 `ZeroDivisionError`。

**建议/验收**：schema 增加取值范围和跨字段规则，Python 计算前执行权威校验，主进程保存也检查结构。错误提示定位具体字段。至少覆盖零长度、负误差、空/错长数组、无效回归输入、非有限数及科学计数溢出。

### F04 · 官方热更新变体被误判为用户修改

**位置**：[热更新合并](E:/agent-project/labreport-writer/main.js:1094)、[安装升级的基线机制](E:/agent-project/labreport-writer/src/main/resource-store.js:98)。

热更新判断用户是否编辑过变体时，比较的是当前文件与**安装目录原版**。若安装内为 V0，第一次热更新变为 V1，第二次更新 V2 时，V1 已不等于 V0，于是被误判为用户修改并保留。安装升级已有 `variantBases`，但热更新路径未使用同等的版本基线。

**建议/验收**：每次成功更新后记录对应官方基线，按“旧官方、用户当前、新官方”三方比较；连续 V0→V1→V2 的纯官方更新必须成功，真正用户编辑须保留并说明冲突所属实验。

## 六、可靠性与工程问题

### R01 · 日常数据保存没有采用资源更新同等的保护

**位置**：[测量数据写入](E:/agent-project/labreport-writer/main.js:399)、[变体保存](E:/agent-project/labreport-writer/main.js:1776)、[状态文件读取](E:/agent-project/labreport-writer/src/main/resource-store.js:7)。

测量值、变体和状态文件使用直接 `writeFileSync` 覆盖。截断后写入失败或异常退出可能损坏 JSON；状态文件解析失败还会影响扫描/同步。`localStorage` 中存有润色全文，也缺少额度耗尽和数据迁移恢复方案。

**建议/验收**：统一临时文件写入、校验和同目录替换；保留最近有效备份与格式版本；损坏时允许恢复，而不是静默当作空数据。通过故障注入验证失败后旧文件仍可解析、界面提示可操作。

### R02 · 任务生命周期仅覆盖窗口内的正常操作

**位置**：[窗口关闭](E:/agent-project/labreport-writer/main.js:165)、[退出逻辑](E:/agent-project/labreport-writer/main.js:212)、[取消任务](E:/agent-project/labreport-writer/main.js:1651)。

关闭仅检查未保存表单，没有处理正在生成的 Python/Word、AI 请求和下载；未发现 `requestSingleInstanceLock`。现有生成锁为单进程变量，两个应用实例仍可能写同一个实验报告或更新目录。

**建议/验收**：根据产品定位启用单实例，或引入跨进程锁；退出时统一中止/等待当前任务、完成清理后退出。测试直接关闭、二次启动、下载中退出、生成中退出和异常结束；不能仅依赖手动“取消生成”按钮的测试。

### R03 · 外部输入与长任务缺少资源预算

**位置**：[下载](E:/agent-project/labreport-writer/main.js:945)、[解压](E:/agent-project/labreport-writer/main.js:1009)、[生成日志](E:/agent-project/labreport-writer/main.js:1542)、[AI 请求](E:/agent-project/labreport-writer/main.js:1715)。

- 下载没有总时限、压缩包大小上限；多个调用共用 `_package.zip`。
- 解压只检查部分路径形态，没有文件数、解压后总大小或压缩比上限。
- AI 请求有手动取消，但没有自动截止时间、输入/输出大小或并发配额。
- 生成期间的 `logs` 数组持续累积，结束后才截断诊断副本；日志 UI 也持续追加文本。

**建议/验收**：设置可配置的总超时及字节、文件数、并发上限；流式计数并在越限时终止；日志改固定容量缓冲；下载使用独立任务 ID 和临时路径。用无响应、断流、超大响应和高压缩比包验证不会永久挂起或耗尽磁盘。

### D01 · 依赖清单与实际安装存在漂移

**位置**：[应用依赖](E:/agent-project/labreport-writer/package.json:1)、[锁文件根条目](E:/agent-project/labreport-writer/package-lock.json:1)、[Python 依赖](E:/agent-project/labreport-writer/物理实验/requirements.txt:1)。

`package.json` 为 1.7.5，锁文件根版本仍为 1.0.0，且锁文件保留当前 manifest 已移除的 `xlsx`。本地 `xlsx@0.18.5` 被标为 extraneous。审计报告命中原型污染与正则拒绝服务公告：[CVE-2023-30533](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6)、[CVE-2024-22363](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9)。

**风险边界**：未发现当前应用源码调用 xlsx；没有认定该包必然进入最终安装包或可经当前用户流程利用。本次没有使用 `npm audit fix` 或重装依赖。

**建议/验收**：整理锁文件，在干净目录使用锁定安装重新审计和构建，检查 asar 中实际生产依赖。固定并记录嵌入式 Python 与依赖版本/摘要；单纯 `>=` 的 requirements 不能复现已发布运行时。对安装产物生成软件物料清单。

### Q01 · 质量门禁覆盖不足且有漏报

**位置**：[测试入口](E:/agent-project/labreport-writer/package.json:7)、[冒烟检查](E:/agent-project/labreport-writer/smoke_test.py:65)、[静态校验命令](E:/agent-project/labreport-writer/validate_schema.py:90)。

`npm test` 仅执行 12 项 Node 回归。Python 静态检查、Word 集成和公式构建是独立命令；仓库未发现提交中的 `.github` 工作流。

另外，`validate_schema.py` 主程序打印结果但没有根据失败返回非零退出码；`smoke_test.py` 计算了必填缺失数量，却只将 `invalid` 加入异常列表，因此仅有缺失项时可能显示未填但仍退出成功。这会削弱自动发布门禁。

**建议/验收**：建立统一验证命令，区分“通过、失败、跳过”；对缺失值、无效值和公式构建失败返回明确非零状态。增加云函数协议、预览依赖接入、IPC 边界与计算已知答案测试，不能只依赖示例数据和代码片段模拟。

## 七、值得保留的设计

- **数据与模板分离**：schema/data/variants/rag 的结构降低了新增实验成本。
- **主进程隔离基础正确**：启用了上下文隔离，关闭页面 Node 集成，桥接采用具体方法，没有暴露任意 IPC 通道。
- **用户文件与安装资源分离**：更新应用时保留用户测量值和自建内容的方向正确。
- **资源事务更新**：候选目录、旧目录备份与失败回滚已有测试，明显优于逐文件原地覆盖。
- **Word 实例精确清理**：真实测试确认没有误杀另一个独立实例，这是重要的桌面安全优点。
- **生成结果识别**：结合退出码和本次文件修改时间，避免简单把旧报告当新成功产物。
- **AI 结果可查看差异、章节内容单独导入**：有助于人工复核；但提示词不能替代数值与公式验证。
- **已有诊断脱敏与日志轮换**：后续应围绕遗漏格式补测试，不必推倒重做。

## 八、进一步优化建议

### 1. 产品体验：让“可以生成”升级为“知道是否可信”

- 将示例数据状态显式标注到实验和生成结果中；数据来源提示不应只藏在说明文档。
- 生成后展示输入快照、单位、关键结果和质量检查摘要；允许逐项复核，而非仅显示成功。
- 建立报告历史：区分“本次生成失败但保留旧报告”和“本次生成成功”，显示版本与时间，避免失败后回到成功状态让人误判。
- AI 导入前比较公式、数字、单位和数据占位符；标记变更并保留原文。长文本从环境变量迁移到有大小限制的临时 JSON 文件，减少长润色内容触及 Windows 环境传递限制的问题。
- 增加启动环境自检：Word COM、Python 模块、可写目录和磁盘空间；把缺组件、数据错误、文件被占用区分开。
- 对完整报告/照片投稿展示实际文件、学生信息和接收方；提供删除请求入口，避免用户误以为只上传变体文字。

### 2. 性能与磁盘占用：先优化明确的重复工作

- `replaceTree` 每次复制整棵用户实验树并保留 `previous`；报告与图片也会被复制，长期使用后可能占用大量磁盘。设置保留数量/期限、存储统计和可见恢复入口。
- 把可更新脚本资源与测量数据、历史报告拆成独立目录，减少更新时复制用户产物。
- 把同步大目录扫描、复制和 DOCX 转换移出主进程阻塞路径；在后台任务中处理，避免窗口卡顿。
- DOCX 当前经历 Buffer→Base64→字符串→Uint8Array 多次复制。改为受控二进制传递或本地资源协议，并加入文件大小限制及按修改时间缓存。
- 预览加载加入实验 ID/请求序号校验，防止切换实验后旧异步请求覆盖新页面。

这些是根据代码结构提出的优化方向；本次没有测量启动耗时、峰值内存或帧率，不给出未经实测的性能提升数字。

### 3. 可维护性：围绕边界拆分，不急于全面换框架

当前主进程约 **1,788 行**、前端约 **3,008 行**、样式约 **2,606 行**。建议先拆出文件权限、更新、生成任务、AI 服务、投稿服务和配置存储；前端按录入、队列、预览、设置、投稿划分模块。

共享请求结构、错误码和版本基线，避免前端/主进程/云函数各写一份规则。清理遗留 Excel 描述及未使用函数；统一 AI 提供商配置来源。引入类型检查可渐进开展，无须为了拆分而立即整体改写 UI。

### 4. 发布与隐私文档

- README 中“26 个实验均支持变体”与目录示例“19/26”不一致，应统一。
- 云函数 README 仍要求安装 SDK，但当前实现使用 Node 内置加密模块；部署步骤和路径格式应与代码一致。
- 不应把“密钥不下发”描述为“匿名签发无风险”，也不应固定承诺云服务费用为零。
- 发布前核验实际安装包签名、版本、哈希和干净环境安装；本次未检查发布 EXE，不能认定当前产物未签名。
- 增补数据备份、保留周期、删除方式、AI 接收方和投稿用途说明。仓库声明中 `ISC` 与“仅用于学习交流”等措辞应澄清一致；本项为文档建议，不作法律结论。
