# 0.70.0 安卓识图录入流程验收

2026-10-27，当前模拟器 emulator-5560，安装包 0.70.0。使用真实应用界面、Android Filesystem、照片保存、Canvas 图片处理、识图校对编辑器及 Repository；仅 LabAI 的状态和模型返回使用本地模拟。

## 六项通过的流程

1. 未配置识图 API 时，点击识别提示先配置，模型完成请求次数为零。
2. 保存 2000×1400 的合成 PNG，实际扫描增强/压缩结果是可解码的 1600×1120 JPEG。处理图可预览；模拟模型结果进入校对界面，没有自动写入数据。
3. 将电子偏转实验 D_x 从 9 点增加为 10 点，Udx 三行同步从 27 个输入变成 30 个输入。保留 `2.8e-` 这类未完成输入，关闭再打开可从原生缓存继续校对，不重新调用模型。
4. 未完成数值阻止录入；修正后关闭“仅填空白”，10 点数组和三组对应电压成功存入本机。布局在 320、430、768、1024 宽度无校对区横向溢出；检查了 320 和 768 的截图，底部操作可见，长内容正常纵向滚动。
5. 离开再进入保留已保存的 10 点数据。再次识别只展示新的 9 点结果；“仅填空白”阻止长度替换，原数据不变。显式关闭该选项后可录入新的 9 点，不残留旧的第 10 点。
6. 多次识别后“清除数据”移除测量数据和原始照片，测量输入均为空。

## 隔离与范围

所有文件读写映射到唯一临时命名空间，仍由原生插件执行。测试结束删除临时目录、恢复桥接并重新加载应用。原有 `files/lab-maker/v1` 下 209 个文件与更新前备份逐字节一致，无缺失、修改或新增。

实际付费 API 调用、学校提交均为零。本次没有调用真实模型，没有测量真实照片的 OCR 准确率，也没有通过安卓系统照片选择器选图或验证系统杀进程后的恢复。校对续接验证的是关闭/重新打开识图及实验页切换，不是进程重启。

本轮未发现需要修改应用源码的新问题，安装包保持 0.70.0；不因增加测试重复升版。

复验：`node scripts/accept-native-ocr-ui.mjs`。证据：`artifacts/verification/native-ocr-0.70.0-1793073040805/`，含 results.json 和四尺寸截图。
