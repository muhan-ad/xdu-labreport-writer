# 0.70.0 安卓进程中断恢复验收

2026-10-27，当前模拟器 emulator-5560，安装包维持 0.70.0。本轮没有修改应用源码或重新打包。

## 独立测试用户

模拟器支持四个 Android 用户，原先只有用户 0。本轮创建唯一命名的临时用户 10，在该用户中启用已有安装包并进行测试。进程终止前同时检查当前用户编号和唯一测试名称，只对该用户执行 `am force-stop --user 10`，没有强制关闭原用户应用。

调试连接按 Android UID 选择进程，避免同包名在多用户环境下连接错进程。测试自己的 Android 用户关闭了短时间自动锁屏，原用户设置未改。

## 四项实际通过

1. **冷启动恢复**：保存学生信息、测量样本、照片和报告后终止进程，再启动应用。学号 `001234` 保留前导零；测量记录内容逐项一致；原始照片、原报告代次和预览恢复。
2. **生成中断**：启动新一轮报告生成，在本地引擎初始化阶段终止进程。重启后上一份已发布报告代次不变、预览可读；再次生成成功，发布新代次。
3. **识图校对中断**：识图仅模拟模型状态和回复，图片处理、原生缓存均为实际流程。编辑未完成数值 `7.2e-`，等待原生校对缓存保存后终止进程。重启后不用配置 API 或再次识别，即可继续该校对；测量记录未被部分编辑覆盖。
4. **清除后重启**：执行清除并等待成功提示，再终止/重启应用。测量输入仍为空，照片没有重新出现。

四次重启的应用 PID 分别为 `19797 → 22867 → 23446 → 24351 → 24718`，系统事件日志和测试记录均留存，不以页面刷新代替进程重启。

## 测试脚本问题及修正

首次脚本把记录固定读为 B 副本，因新用户第一次保存只生成 A 副本而报错。这是测试假设错误；脚本改为读取两份记录并选择最新可用代次，随后完整测试通过，没有改动应用双副本写入方式。

独立用户首次流程耗时明显高于之前原用户的预热场景，报告生成观察到约 69–77 秒；本轮不将其当作手机性能结果，也不宣称启动/生成速度已完成真机优化。

## 数据与清理

测试完成切回原用户，已复查 UserManager，临时用户及测试进程均已删除。原用户应用仍保持原 PID 17690；原有 209 个数据文件和三份非 WebView 偏好配置与备份逐字节一致。实际学校提交、付费 API 请求均为零。

证据：`artifacts/verification/native-recovery-1793074892857/`，含 state.json、results.json 和仅该测试用户的进程事件日志。复验脚本 `scripts/accept-native-recovery.mjs` 只接受带唯一测试名称的非零用户，不会对原用户终止进程。

## 边界

这是应用进程终止/重启测试，不是 Android 整机重启、系统内存压力、WebView 单独崩溃、最终文件写入瞬间断电、后台长任务继续运行或真实设备测试。未在发布文件的最终写入阶段终止进程。当前报告队列仍是应用内任务，不能据此承诺系统杀死进程后自动继续生成。
