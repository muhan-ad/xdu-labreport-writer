# 0.70.0 报告生成耗时定位

2026-10-27，本轮只采用测试和测量工具改进，没有更新应用或采用性能候选改动。源码报告 Worker 已恢复为冻结 0.70.0 APK 中的原始字节，SHA-256 为 `b7fa7a171a60bad977fa96afe08f1e6029313e21fb0e4e46a78553f857fbbe86`。

## 原用户前台测量

在原用户 0 中，每轮创建独立的真实 APK Worker，以相同螺线管样本生成报告，不读写已有实验记录。通过 CDP 仅给该 Worker 添加计时钩子，记录本地资源读取、摘要和阶段进度，结果后终止 Worker。

原始安装版三次耗时约 14.44、12.36、12.42 秒。其中运行环境初始化约 9–11 秒，实际报告生成约 3.3–3.5 秒；记录的摘要计算总时长约 44–73 毫秒。不能把这个结果直接推广到其他设备或所有实验。

原用户本轮没有复现临时新用户此前 69–77 秒的生成时间。新用户初始化、环境负载和缓存等因素尚未逐一隔离，不能断言先前慢速只由某一个因素造成。前台测量也不代表冷启动、后台任务或整机压力场景。

证据：`artifacts/verification/native-report-profile-1793076031550/`。

## 未采用的候选

尝试把自有安装资源改为每批最多三份读取，仍逐份校验摘要，并保持 Python wheel 安装和文件写入的原顺序。候选没有绕过校验、保留常驻 Python 或更改计算公式。

先后运行两版时存在明显的后测更快现象，因此没有把先后测得差值当作收益。进一步使用相同 Blob 加载方式、相同前台用户和样本，在六轮中交错运行原版/候选：

| 轮次 | 原版（毫秒） | 候选（毫秒） |
| --- | ---: | ---: |
| 1 | 11010.6 | 10475.0 |
| 2 | 10638.3 | 10346.4 |
| 3 | 10779.2 | 10766.5 |
| 中位数 | 10779.2 | 10475.0 |

中位数仅改善约 2.8%，最后一组几乎相同，样本量不足以证明稳定提升。因此撤回候选，不为此增加运行时改动或发布新版本。计时数据存在调用/调度开销，资源请求可重叠，其各项耗时不能简单相加等同于总时长。

对照证据：`artifacts/verification/native-report-profile-1793076435647/`，含 decision.json。候选源码保留为实验 artifact，不再位于应用资源中。

## 验证和后续方向

新增三项 Worker 加载协议测试：安装顺序与初始化完成条件、损坏 wheel 被拒绝、已验证资源包覆盖逻辑。完整 320 项测试通过，冻结 APK 125 项资源与构建资源再次校验一致。原有 209 个数据文件保持完全相同；已释放测量 Worker 并重新载入测试页面，安装包保持 0.70.0。

初始化是当前样本中的主要耗时，更值得下一步验证的是批量任务活动期间的运行环境复用。该方向尚未实现或承诺收益，需要同时验证实验间状态隔离、资源切换、取消和失败、暂停/结束后的内存释放，不能简单把 Python 永久留在后台。
