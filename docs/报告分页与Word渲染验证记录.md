# 报告分页与 Word 渲染（0.53.0）

实际渲染发现两类问题：刚体报告中表头可留在上一页而数据从下一页开始，思考题题目可位于页尾而答案从下一页开始。本轮在移动端报告适配层修复分页，未改动桌面源码或实验计算。

## 修复

- 标题与下一段保持相邻，思考题题目跟随答案首段。
- 逐次追加文字与内联公式组成的题目，在保存前按已完成的段落补齐规则；RLC 第二题覆盖这种路径。
- 表格首行设置跨页重复表头，表头跟随首个数据行，每个表格行避免拆到两页。允许长表继续跨页，不强制把整张表挤在一页。
- 这些规则用于普通生成和章节关闭生成，不改动原有章节过滤、正文、数值、公式或图片内容。

修复位于 `src/engine/runner.py`，因此需更新 APK；重新生成的报告使用新分页，已有文件需重新生成才能应用。没有通过单独实验数据包修改手机解释器代码。

## 实际 Word 验证

使用原版样本与实际 WebAssembly 引擎生成 28 份报告。标准 `render_docx.py` 因本机没有 LibreOffice 无法运行，改用安装的 Word 导出 PDF；文档处理依赖由本线程的 workspace dependencies 定位。Word 仅在没有现有 Word 进程时创建独立自动化实例，禁用宏、只读打开、禁用最近文件记录、拒绝活动内容和外部关系，导出后不保存源 DOCX，正常退出本次实例。

修复前后各 28 份报告均成功导出，共各 136 页。原文件哈希在导出前后相同；渲染输入分别保存在 `artifacts/verification/report-layout/docx-before` 和 `docx-after`。后者的 28 个 SHA-256 均与最终 Word 导出记录一致，避免后续测试重新生成文件后失去输入依据。

逐页筛查全部 136 页，未发现文字或图片越出纸张边界、公式数量丢失、表格网格超过版心、检测范围内的原样 LaTeX 命令或替换字符。初次版心提示全部为中文标点悬挂，未作为缺陷修改。

人工检查了刚体和螺线管的页面总览，并放大检查刚体第 3、7 页和螺线管第 2 页：题目与答案首段保持在同页，跨页表头重复，表头不再孤立。自动筛查和代表页检查不等于对全部公式的科学正确性或每行排版完成了人工验收，WPS 与手机查看器也尚未复核。

## 回归证据

- 实际 DOCX 比较：28 份正文/公式文本及内嵌图片内容逐项相同；1011 条原生 Word 公式保持不变。
- 分页结构检查：45 张表、148 个标题、53 个编号问句通过。`scripts/test-report-runtime.mjs` 已加入实际生成文件的表头/表行规则检查，后续 `npm run test:reports` 会继续执行。
- 28 个普通生成、28 个关闭章节生成通过；普通报告共 1011 条公式，关闭章节样本共 843 条。
- 28 个实际 Worker 自定义思考题队列通过，共 903 条公式；包含不完整数据隔离、失败项修正后重试及仓储回读。回答使用模拟端口，没有真实模型调用。
- 247 项逻辑测试通过。原生构建与安装包校验见 `artifacts/preview/verification-0.53.0.json`。

主要证据目录为 `artifacts/verification/report-layout/word-before`、`word-after-final`，其中包含 Word PDF、页面总览、关键页图片及 `layout-screening.json`；`pagination-results.json` 保存结构/内容核对结果。

本轮没有访问真实用户报告、修改真实测量数据、安装设备、执行学校业务或发布云端。整体移植、完整科学复核、真实手机/平板性能、系统生命周期和 iOS 验收仍待继续。
