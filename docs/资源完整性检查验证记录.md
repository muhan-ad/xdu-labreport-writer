# 0.14.0 资源完整性检查

设置的“实验资源”新增检查入口。开始后逐个核对安装资源并展示进度，可取消、重新检查；完整时显示绿色“资源完整”，异常时列出完整资源路径及“缺失 / 长度不符 / 校验不符 / 读取失败”。长列表可滚动，结果可导出给用户自行保存或分享。离开页面取消当前检查，旧任务结果不会覆盖新页面。

## 范围及实现

核对当前 APK 内的全部 assets 及原生 .so 文件，包含页面/查看器、实验目录和明确名称映射、离线 Python/WASM 与依赖、实验脚本/模板归档、OCR 模型及四种架构的 OCR 库。当前为 89 个实际安装文件，解压后合计约 74.2 MB（界面按 1024 换算显示约 70.8 MB）。归档整体哈希覆盖其内部文件内容，不把归档内文件数重复计入安装文件数。

构建时，在依赖资源与裁剪后的原生库合并完成后生成带版本、长度、SHA-256 的清单；清单本身由 APK 签名覆盖，避免自我哈希循环。对关键资源及离线报告清单逐项检查，不能把缺少关键文件的构建生成成“完整”清单。原生库变化也会触发清单重新生成。安装后的检查直接用 ZipFile 流式读取当前 APK，以 64 KB 缓冲计算，不读取或修改测量数据、照片、账号、密钥或报告，不需要网络。

该功能核对安装资源的文件完整性，不代替实验数据合理性和报告计算结果验证，也不提供自动覆盖或删除用户数据的修复操作。异常提示先备份再覆盖安装完整安装包。资源更新/修复维护仍待后续迁移。

## 验证

- 45 项领域测试保持通过；29 项业务 Java 单测通过（另有 1 项模板示例）。新增 4 项资源引擎测试覆盖完整资源、实际字节计数、全部缺失/损坏类型、读取中取消与流关闭、重复/越界路径及空清单拒绝。
- Android 实际安装 APK 的 4 项组合：真实 89 个资源全部通过；重复检查；并发拒绝；取消与旧取消不影响新任务；页面离开和迟到结果隔离；96 项模拟缺失/损坏清单完整显示及导出。正常结果来自实际 APK；异常长列表是明确的界面模拟，缺失和损坏读取由原生引擎样本验证，没有修改真实安装文件。
- 手机/平板 320/360/430/768/1024/1280 CSS px 的正常/异常状态截图和横向溢出检查；人工查看 320 正常状态及 768 长列表。系统导出面板取消，未选择发送对象。
- 打包验证器比较清单与 APK 全部 assets/.so 的集合、长度和哈希，并核对当前 dist、原生读取脚本和别名表。正常 APK 通过；测试 APK 故意修改 report-reader.js 的一个字节，验证器明确失败并指出文件。损坏包未安装，测试后删除。

证据：artifacts/verification/resources-native.json、resources-{complete,problems}-*.png；日志位于 E:/tools/app-maker/logs/resource-*。

## 构建与边界

统一构建入口 scripts/build-android.ps1 已在复制最终 APK 前调用 scripts/verify-apk-resources.mjs，校验失败不交付。验证器只读取 APK，不解压执行内容；使用锁文件中现有 Capacitor 工具依赖的 ZIP 读取库，不增加手机端依赖。

已验收当前通用 APK；Android App Bundle 拆分安装、物理手机和 iOS 尚待验收。此前报告、识图和学校功能证据按版本沿用，不冒充本轮全部回归。没有执行真实学校选退课、报告上传、付费 API 或云端发布，完整移植目标仍在推进。
