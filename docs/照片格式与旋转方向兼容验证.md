# 0.74.0 照片格式与旋转方向兼容

本轮为移动项目本地修复与 emulator-5560 验收，没有发布或修改桌面原版。

## 已复现的问题

应用接受 JPEG、PNG、WebP 原始照片。原版 Word 图片插入器不能直接写入 WebP，但会捕获异常后以占位文字继续生成。0.73.0 的真实 WASM 测试因此在“原图必须嵌入”断言失败，不能将生成成功视为照片已插入。

另以 JPEG EXIF 方向 6 的非对称四色照片验证：浏览器按方向信息显示 400×600，而旧 Word 报告仍显示原始 600×400；实际 Word 页面已复现两者方向不一致。

## 修复

只在报告任务内准备兼容副本，不写回原照片文件。普通未旋转 JPEG/PNG 保留字节；WebP 转成无损 PNG，旋转或镜像照片按 EXIF 转换像素并清除副本方向信息。其后继续复用 0.73.0 的等比例页面适配，不裁剪、不缩减原图分辨率。

最终文档必须包含该照片摘要对应的媒体，否则明确报错并保留上一份已发布报告，不再以“已生成”掩盖照片未写入。本机照片保持原始字节；报告中的兼容副本可能与原文件摘要不同，测试相应核对副本而不要求错误的原字节嵌入。

## 验证证据

- scripts/test-photo-layout.py：7 项实际文档/图片回归，包括八种 EXIF 方向的独立手列像素映射、无损 WebP（含透明度）、普通 JPEG/PNG 字节保持、损坏输入、照片缺失、长图适配及重复执行。八种映射使用 PNG EXIF；JPEG 方向 6 另经实际 WASM 与 Android 验证。
- 实际 WASM：普通 PNG 28 实验、WebP 28 实验全部通过；旋转 JPEG 单独生成通过。照片插入、公式映射和分页标记均核对。对应 artifacts/report-tests/074-with-photo/、074-webp-all/、photo-formats/after-orientation6/。
- 独立科学对照：CPython/WASM 各 110 项，18 组输入变化各 93 项通过；两种单位错误与螺线管旧重复平均缺陷仍能被拒绝。本轮没有修改计算算法。
- Word 实际渲染：旋转样本 8 页、WebP 样本 7 页，照片所在完整页面已查看；修复前 JPEG 首页面与修复后照片页面方向对比已保存。不是所有真实照片、所有 WPS 版本的全面验收。
- Android 实际 UI：WebP 与旋转 JPEG 各五项流程通过，涵盖导入、取消重试、生成/预览、四尺寸图表和重新打开；原照片从原生存储回读，字节与输入一致。实际 DOCX 的 PNG 为 600×400／400×600，四角色块逐像素抽样与 WebView 预览完全一致，方向标签不再残留。

Android 证据为 artifacts/verification/native-report-ui-0.74.0-1793100608903/ 与 native-report-ui-0.74.0-1793100628474/，其中 photo-display.json、photo-compatibility.json 记录显示与回读核对。Word 证据为 report-layout/073-before-exif/、074-after-exif/、074-after-webp/。失败的原 WebP 测试保留为 photo-webp-before.log，不计通过。
