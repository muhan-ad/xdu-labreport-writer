### R01：贡献对象公开读取

- **证据：** 不带认证的 GET 和 HEAD 均能访问当前反馈对象和固定地址的审核状态文件，返回 200；未读取展示正文。主数据包公开下载是合理需求，贡献数据和审核状态不应沿用这一访问规则。
- **影响：** 知道对象地址的人能够读取对象。状态文件结构还包含贡献对象键，可能进一步暴露反馈/报告位置。匿名列举被禁止不足以解决问题。
- **建议：** 将 `contributions/`（包括 `_meta/`）设为仅受控身份可读取；主应用使用限时、限对象的上传凭证，管理端使用所需权限的身份读取。仅公开版本清单和实验数据包。先核对实际 ACL/桶策略来源，再调整，避免误伤公开更新通道。
- **验收：** 匿名 GET 贡献/状态返回 403；认证管理端读取正常；公开更新清单和 ZIP 仍返回 200。另查历史对象访问日志，评估是否已有非预期访问。

### R02：Word 预览可保留可执行协议

- **位置：** [管理端 HTML 清理函数](E:/agent-project/labreport-writer-manager/ui/app.js:54)、[主进程 IPC](E:/agent-project/labreport-writer-manager/main.js:113)。
- **复现：** 使用管理端实际安装的 Mammoth 1.12.3 转换临时 DOCX，超链接地址包含 `java`、换行符、`script:void(0)`。转换结果保留该地址；清理正则未拦截，而 URL 解析识别为 `javascript:`。只做了惰性转换和解析，没有在桌面执行脚本。
- **影响：** 在用户点击构造链接等条件下存在脚本执行风险。管理端未配置 CSP，IPC 未验证调用来源，渲染层又持有可调用后台的桥接能力，会放大文档预览风险。
- **建议：** 使用成熟 HTML 白名单清理器；只允许明确的链接协议，规范化控制字符；隔离预览区，禁止脚本及导航；为管理端添加 CSP、导航限制和 IPC 来源/参数校验。补真实 Electron 预览回归用例。

### R04：演练内容和未通过校验的内容进入真实审核路径

- **位置：** [处理流水线](E:/agent-project/labreport-writer-manager/backend/server.py:212)、[AI 演练分支](E:/agent-project/labreport-writer-manager/core/agent.py:43)、[合入接口](E:/agent-project/labreport-writer-manager/backend/server.py:622)。

- **影响：** 尚未真实解析、内容不合格或处理失败的材料可能进入推送列表。`/api/merge` 和推送流程没有统一强制执行最终内容校验。
- **建议：** 真实模式缺配置就明确拒绝自动处理；演练输出只能进入独立空间。将“已处理”“待复核”“审核通过”“已发布”分开；最终合入/发布强制校验，不能只靠界面上的校验按钮。

### R05：发布失败会破坏仍在使用的旧下载地址

- **位置：** [发布顺序](E:/agent-project/labreport-writer-manager/core/package.py:326)。
- **复现：** 假 COS 记录顺序为 `move_old → upload_new`；模拟新包上传失败后，旧包原地址已不存在，清单仍指向旧包。
- **影响：** 新发布失败也能让正常用户无法更新；已读取旧清单、稍后才下载的客户端也可能失败。
- **建议：** 新 ZIP 上传到不可变地址并验证可读后，再更新清单；旧 ZIP 保留在原地址一段时间，延后清理。发布失败不得改变当前可用版本。

### R06：增量包不能覆盖跳版本用户

- **位置：** [增量打包](E:/agent-project/labreport-writer-manager/core/package.py:87)、[唯一最新清单](E:/agent-project/labreport-writer-manager/core/package.py:276)、[主应用合并](E:/agent-project/labreport-writer/main.js:1199)。
- **场景：** 1.0.2 只更新实验甲，1.0.3 只更新实验乙；仍在 1.0.1 的用户直接取得 1.0.3，甲的更新不会补齐，却会被记录为最新版本。当前协议没有增量基线或补丁链。
- **依赖风险：** `with_common` 默认关闭；实验脚本依赖新版公共函数时，旧用户可能只收到调用方而没有实现。新旧构建都标 1.7.6 时，`minAppVersion` 无法区分。
- **建议：** 对本项目优先使用“最新包为完整快照”的简单方案；如果保留增量，必须增加基线检查、完整包兜底和依赖校验。目前线上 1.0.1 实测完整，不能据此断言以后增量发布也安全。

### R07：源码合入、审核状态与云端发布不是一个可恢复流程

- **位置：** [推送实现](E:/agent-project/labreport-writer-manager/backend/server.py:267)。
- **影响：** `merge_candidate()` 先写主仓库，再写 `merged` 状态，最后才打包上传。签名、网络或上传失败后，源码已经改变、状态显示已合并，批量推送只选择 approved 时可能漏掉这些条目。
- **建议：** 保存发布任务及候选清单，区分“已合入待发布”和“已发布”；先在候选目录构建校验，发布成功后确认状态。保留恢复点，失败能重试同一任务并明确显示哪些步骤已完成。

### R08：上传与同步之间缺少批次完成标记

- **位置：** [主应用逐文件上传](E:/agent-project/labreport-writer/src/renderer.js:2605)、[管理端同步](E:/agent-project/labreport-writer-manager/core/sync.py:31)。
- **复现：** 第一次仅有照片时同步；随后同目录加入 `manifest.json`，第二次同步没有下载新增文件，因为整个目录已登记为 known。
- **影响：** 附件或元信息永久漏收。另一台管理端共享云端状态，但没有当前机器的 inbox，也可能跳过下载。
- **建议：** 所有附件完成后提交批次完成标记及文件表；管理端只处理完成批次，按文件摘要/大小补齐本机缺失对象。云端审核状态不能代替本机下载状态。

### R09：多人审核与重复发布缺乏并发控制

- **位置：** [状态读改写](E:/agent-project/labreport-writer-manager/core/states.py:41)、[异步打包入口](E:/agent-project/labreport-writer-manager/backend/server.py:638)。
- **复现：** 两个线程同时从同一状态开始写不同条目，最终只剩 1 条，预期 2 条。`expect_rev` 只是读后比较，实际写入没有原子条件；主要调用也未传此参数。
- **影响：** 审核记录覆盖、署名丢失；两个发布任务还能使用相同版本号和同一 ZIP 临时路径。
- **建议：** 状态写入使用服务端原子版本条件/事务或按记录独立存储；发布采用跨管理端锁和唯一任务标识。本机互斥只能解决单进程问题，不能替代多人并发控制。

### R10：OCR 独立服务被主聊天地址覆盖

- **位置：** [OCR 地址选择](E:/agent-project/labreport-writer/main.js:1871)、[识别参数](E:/agent-project/labreport-writer/src/ocr.js:669)。

- **影响：** 独立识图密钥保存时通常绑定识图预设地址，识别时却取另一个地址，触发地址不匹配或请求错误。密钥绑定保护可能阻止发送，不能据此断言密钥已泄漏。

- **影响：** 后台校验的是应用共享启动令牌，登录没有颁发用户会话；有 IPC 能力的调用者可不经过登录执行接口，且 `body.user` 可自行指定。初始账号密码信息还出现在源码注释中，密码哈希采用单轮 SHA-256。
- **边界：** 后台绑定本机环回并要求启动令牌，不能把此问题描述成“任意互联网用户直接登录”。但多人身份审计及被污染渲染页面的防护不足。
- **建议：** 若只作个人工具，明确简化账号定位；若保留多人账号，就采用服务端会话、操作身份绑定、首次改密及合适的密码哈希算法。

### R13：OCR 会话与照片保存时机不稳健

- **位置：** [开始识别](E:/agent-project/labreport-writer/src/ocr.js:622)、[照片提前保存](E:/agent-project/labreport-writer/src/ocr.js:642)、[结果应用](E:/agent-project/labreport-writer/src/ocr.js:756)。
- **影响：** 关闭弹窗没有取消后端请求，结果没有绑定原实验 ID；重新打开或更换实验后，晚到结果可能污染当前状态。识别确认前就异步保存原图且忽略失败，取消/失败也可能替换原照片。
- **建议：** 使用实验 ID 和请求 ID 固定会话；关闭/换图取消旧请求，丢弃过期结果；确认后提交照片和字段，保存失败必须可见。矩阵数字输入统一严格解析，避免 `parseFloat` 接受带非法尾部的文本。

### R14：OCR 等待时间与底层超时冲突

- **位置：** [OCR 120 秒设置](E:/agent-project/labreport-writer/main.js:1913)、[网络层 15 秒空闲超时](E:/agent-project/labreport-writer/src/main/network.js:33)。
- **影响：** 模型超过 15 秒没有返回数据时，即使总期限是 120 秒也会先报网络超时；界面本身提示大图可能需要 10～30 秒。
- **建议：** 分开连接、响应空闲和总请求期限，并允许 OCR 配置合理的等待时间；添加延迟响应回归测试。未发起真实计费模型请求来测量发生频率。

### R15：网络安全策略尚未统一

- **位置：** [主聊天直接 fetch](E:/agent-project/labreport-writer/main.js:1952)、[管理端 URL 校验](E:/agent-project/labreport-writer-manager/core/netguard.py:17)、[文档解析请求](E:/agent-project/labreport-writer-manager/core/mineru.py:46)。
- **影响：** 主聊天未使用已有 DNS 连接校验网络层，也缺少统一总超时/响应上限。管理端先解析校验域名，再由 requests 重新连接，默认跟随重定向，且允许 HTTP；不能保证每一跳都只访问公网 HTTPS。
- **触发前提：** 通常需要恶意/错误自定义服务地址、服务端重定向或 DNS 变化；本轮没有访问内网来验证利用。
- **建议：** 统一传输层，限制协议并验证实际连接地址和每次重定向；敏感头不跨来源转发；设置响应上限与取消机制。

### R16：同步入口缺少统一对象键防护

### R19：资源边界与重试规则不完整

- **位置：** [后台读取请求体](E:/agent-project/labreport-writer-manager/backend/server.py:516)、[前端桥接重试](E:/agent-project/labreport-writer-manager/main.js:113)、[COS 下载](E:/agent-project/labreport-writer-manager/core/cos_client.py:74)。

## 六、进一步优化建议

1. **先保持发布流程简单。** 最新数据包采用完整快照，后台单任务发布；现有包约 442 KiB，没有必要先引入复杂补丁链。
2. **上传闭环可观察。** 为贡献批次、处理任务、发布版本使用关联 ID，显示“上传完成/下载完整/校验失败/待复核/已发布”，不把多个状态压成一个成功提示。
3. **发布前统一检查。** 公私钥配对、真实客户端验签、实验依赖、完整性、候选校验、生产配置就绪都在同一发布预检中执行。
4. **依赖可复现。** 管理端 Python requirements 只有最低版本约束，建议记录经过验收的锁定版本和运行时版本；用干净环境安装验证。保留 npm 锁文件与固定构建命令。
5. **配额适度加强。** 凭证函数限额保存在进程内 Map，冷启动/多实例之间不共享。小项目可先配置网关限流、总量/费用告警及过期残片清理，再按需要引入持久配额。
6. **统一保留与删除规则。** 审核资料按用途设置保留期，发布包保留可回滚版本；删除前能够预览影响并保留必要恢复点。
7. **隐私提示准确。** OCR 是否识别学生信息的开关不等于裁掉照片上的个人信息；发送前提供裁剪/遮挡提示，反馈与报告存储落实访问隔离。
8. **补针对性回归。** 重点覆盖本报告复现的失败顺序、跨版本更新、并发、晚到附件、独立 OCR 配置与预览安全；避免只增加验证成功路径的测试。
