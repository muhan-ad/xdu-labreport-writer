# 运行验证清单

> 对应应用 v1.7.5。下列为发布前应人工/自动化覆盖的运行场景。静态检查（`smoke_test.py`、`validate_schema.py`、`node --check`）之外的运行时行为以此清单为准。

## 数据与表单

1. **首次保存后切换实验并重新读取**：对某实验首次「保存修改」（触发镜像到用户数据目录）→ 切到别的实验 → 切回 → 应读到你刚保存的值，而非出厂示例。
2. **未保存数据直接生成**：修改字段不保存直接点「生成报告」→ 应先自动保存再生成，报告使用当前界面值；保存失败应中止并提示，不启动 Word。
3. **未保存数据切换实验**：修改字段不保存切换实验 → 应弹「保存并切换 / 取消」，取消则保留修改不切换，不静默丢弃。
4. **清除/填入默认**：清除后所有格子（含科学计数法指数框）为空；填入默认恢复 sample.json 全表（含表格类字段）。

## 报告生成

5. **数据缺失且存在旧报告**：清空必填数据后生成 → 应显示失败（generate.py 打印缺失列表），且**不把目录里的旧 docx 误判为本次成功**。
6. **目标报告被 Word 占用**：手动用 Word 打开该实验报告后生成 → 应显示失败（保存被占用），不崩溃。
7. **取消生成 + 手动 Word**：生成进行中点「取消生成」，同时此前/期间手动打开的 Word 不应被结束，仅清理本次任务启动的 Word。

## AI 润色

8. **生成中切换实验并导入**：对实验 A 发起润色 → 结果返回前/后切到实验 B → 点导入应被拦截（提示结果来自实验 A），不注入 B。

## 数据热更新

9. **四类更新包**：分别用 合法包 / 损坏 zip / 含越界路径包 / 中途失败包 测试「检查实验数据更新」：合法包成功合并且 data.json 不被覆盖、用户改过的 variants.json 保留；非法包不改动现有文件且旧 common 仍可用。

## 升级

10. **安装新版本后保留用户数据并更新程序资源**：覆盖安装新版后，用户填写的数据、自建变体、报告保留；所有实验使用新版 generate.py/schema/知识库/common。

## 更新通道

11. **新版检查更新**：显示当前版本；发现新版本弹窗展示夸克/GitHub 下载入口（不自动下载）。
12. **旧版（≤1.6.x）检查更新**：读 latest.json 的 url/fileName 自动下载并打开安装程序。

---

*自动化部分见 `smoke_test.py`（异常时退出码非零）与 `validate_schema.py`（畸形输入返回结构化错误）。*
