> 这份文档假设你完全不懂编程，从零开始解释这个应用是怎么运转的。
> 阅读顺序建议：第 1、2 章建立世界观 → 第 3~6 章看核心机制 → 第 7~10 章看数据与更新 → 附录查术语。

## 第 1 章 这个软件是干什么的

「实验报告编写」是一个 Windows 桌面应用，服务于大学物理实验报告的撰写：

1. 你选择一个实验（共 26 个，如"刚体转动惯量的测量"）；
2. 在表单里填入你的测量数据（表格、数组、科学计数法都有）；
3. 点「生成报告」，软件自动完成：数值计算（含不确定度）→ 选措辞变体 → 画图表 → 在本机排出一份格式规范、带原生公式的 .docx 实验报告；
4. 你还可以用 AI 润色章节文字、用 AI 改写措辞（变体）、把自己的好变体/报告/建议上传给开发者，以及一键检查更新。

它背后由四块拼成：**桌面外壳（Electron）+ 计算与排版引擎（纯 Python）+ 数据文件（一堆 JSON）+ 云端服务（腾讯云 COS 与云函数）**。下面逐层拆。

## 第 2 章 基础世界观：这个软件由什么构成

### 2.1 什么是 Electron

你平时用的 Chrome 浏览器能显示网页、能执行 JavaScript 逻辑。
**Electron = 把"一个浏览器内核 + 一个 Node.js（能读写文件、联网、运行程序的 JavaScript 运行环境）"打包进同一个窗口**，做出来的就是桌面应用。VSCode、微信桌面版都是 Electron 做的。

所以本应用本质是：**一个显示自己内置网页的浏览器窗口 + 一个能干杂活的后台程序**。

### 2.2 三个角色（进程）

Electron 应用运行时分成几种"进程"（可以理解为各干各的独立程序）：

| 角色 | 文件 | 通俗理解 |
|---|---|---|
| **主进程** | `main.js` | **大管家**。唯一能碰你电脑（读写文件、启动 Python、联网下载）的角色 |
| **渲染进程** | `src/` 里的网页 | **前台服务员**。只负责画界面、响应点击，**没有权限直接碰你的电脑** |
| **桥接层** | `preload.js` | **传声筒**。服务员想要什么，通过它写好的"菜单"向管家申请 |

为什么要分开？安全。网页部分就算被人注入恶意代码，它也碰不到你的文件系统——所有危险操作必须经过管家审核的通道。

### 2.3 IPC：管家和服务员怎么对话

它们之间靠"传话"沟通，术语叫 **IPC（进程间通信）**：

```
界面代码：  const r = await window.labAPI.writeData(路径, 数据)   ← 递单子
preload.js： writeData: (p, d) => ipcRenderer.invoke('write-data', p, d)  ← 翻译
main.js：    ipcMain.handle('write-data', (event, p, d) => { ...真正写文件... })  ← 干活
```

每个功能都要在 `preload.js` 的"菜单"上登记过才能用——没登记的能力界面根本看不见。

### 2.4 JSON：全应用通用的"数据表格"

JSON 是一种纯文本的数据写法，像这样：

```json
{ "g": 447.5, "T": [1.387, 1.389, 1.386], "姓名": "张三" }
```

键值对、数组、嵌套都行，人能看懂、机器能解析。**本应用里几乎所有"数据"都是 JSON 文件**：表单定义、你填的数、变体文本、更新清单、反馈内容…… 只有两类例外：生成的报告是 Word 文档（.docx，本质是压缩的 XML），照片是图片二进制。

## 第 4 章 核心机制一：表单是怎么"长"出来的

你看到的录入表格**不是写死的**，而是由 `schema.json` 动态生成的。schema 里每个字段声明了类型：

| 类型 | 界面表现 | 例 |
|---|---|---|
| `number` | 单个数字框 | 圆环质量 m |
| `array` + `length` | 一排 N 个数字格 | 5 次周期测量 T |
| `matrix` + rows/cols/rowLabels | 表格 | 7 量 × 5 次测量矩阵 |
| `science` | 尾数 × 10^指数 双框 | 电流常数 Ki（2.7 × 10⁻⁹） |
| `text` | 文本框 | 备注 |

流程：选中实验 → 界面通过 IPC 读 `schema.json`（画表单）和 `data.json`（回填你填过的值）→ 你编辑 → 点「保存修改」→ 界面把表单收集成 JSON → IPC `write-data` 写回磁盘。

配套按钮逻辑：
- **清除数据**：所有格子置空（科学计数法连指数框一起清空；只填尾数时保存会自动补默认指数）；
- **填入默认数据**：整表恢复为 `sample.json` 里的出厂测试数据（防止 schema 没给默认值的表格类字段填不满的老问题）；
- 改过未保存时关窗口会弹"是否保存"拦截。

## 第 5 章 核心机制二：一份报告是怎么生成的

点「生成报告」后发生的事，按时间顺序：

### 第 1 步：管家准备"包裹"
主进程 `run-generate` 收到：实验路径、你的学生信息、变体选择（哪个章节用第几套）、AI 润色覆盖文本。它把这些**塞进环境变量**（传给子程序的隐形便签）：

```
LAB_STUDENT_NAME/ID/CLASS/DATE   学生信息
LAB_VARIANTS = {"实验原理": 2, ...}   每章节选中的变体序号
LAB_POLISH   = {"误差分析": "润色后的文字"}  要覆盖的章节
```

### 第 2 步：启动 Python 计算
主进程用**内置的 python-runtime** 运行该实验的 `generate.py`（工作目录=实验文件夹）。脚本自己会：

1. `json.load` 读 `data.json`（你的数据）；
2. `_compute()` 函数做物理计算：平均值、A/B 类不确定度、合成标准不确定度、逐差法……产出一个结果字典（如 `a_mean=0.1234, rel_err_a=2.1`）；
3. 调用公共库 `variants.compose()` 拼章节文字（见第 6 章）；
4. 用 matplotlib 画数据图（如伏安特性曲线），存为图片；
5. 调用 `docx_report.py` 排版。

### 第 3 步：本机直接写出 .docx（python-docx + OMML）
`docx_report.py` 用 `python-docx` 直接写文档结构，公式走 **LaTeX → MathML → OMML** 转换后写进 XML：

```python
mathml = latex2mathml.convert(r"a\sin\theta = k\lambda")   # LaTeX → MathML
omml   = mathml2omml.convert(mathml)                       # MathML → OMML
段落._p.append(parse_xml(omml))                             # 写入段落
```

报告里的公式**不是图片，是可以双击编辑的真公式**，而整个生成过程不启动 Word。旧版走 Word COM 与 `OMaths.BuildUp()`，该步骤在部分 Word 版本上会把公式降级为线性文本（用户端表现为"最后一步失败"），已于 2026-09 迁移，详见 docs/Word迁移说明.md。

### 第 4 步：回程
Python 往屏幕上打印日志（进度、缺数据提示）→ 主进程逐行捕获转发到界面「生成日志」；其中有一行特殊标记 `.LAB_SECTIONS_JSON:{...}` 被单独截下——那是**本次报告各章节的最终原文**，存成 `.lab_sections.json`，供之后 AI 润色时取原文用。

## 第 6 章 核心机制三：变体系统（让每份报告措辞不同）

### 6.1 变体是什么
`variants.json` 里每个章节（实验原理/实验方法/误差分析/结论）有 5 段可替换的文本。生成时按你选的序号（或随机）取一段。文本里可以埋两种"活字"：

- `$...$`：行内公式，最终被转换成 Word 原生公式（OMML）；
- `%%DATA:a_mean:%.4f%%`：数据占位符，compose 时替换成你数据的计算结果（%.4f 是格式）。

### 6.2 合成优先级（compose 双路径）
```
1. 取变体文本（按 LAB_VARIANTS 序号）→ 替换 %%DATA%%
2. 若 LAB_POLISH 里有该章节的润色文本 → 整段覆盖变体 → 再替换 %%DATA%%
```
即：**润色 > 变体选择**。两者最终文本都会进 `.lab_sections.json` 缓存。

### 6.3 AI 调整变体
变体卡片每行的「AI 调整」：把当前变体文本+你的指令发给 AI → 生成新措辞（强制保留公式和占位符）→ 可编辑 → 保存后**追加进该实验的 variants.json**（下次生成就能选它），默认同时**归档一份到自建变体库**（可取消勾选）。生成中可以点「取消生成」真正中止请求。

### 6.4 自建变体库
`%APPDATA%\labreport-writer\自建变体\<实验名>.json`，结构与 variants.json 相同。设置 →「自建变体」页可以：按实验/章节浏览、删除（**会同步删掉实验里的同文本条目**，不留残留）、恢复到实验、导出成 `自建变体_实验名.json`、（开发者模式）批量导入。主界面有自建变体的实验会**置顶并挂"自建"徽章**。

## 第 7 章 数据放在哪里（三层分离铁律）

这是整个应用最重要的设计，一句话：**你的东西永远不放在软件安装位置**。

| 层 | 位置 | 内容 | 谁能改 |
|---|---|---|---|
| 出厂数据 | 安装目录 `resources\物理实验\实验脚本` | 脚本/schema/示例数据/变体/知识库 | 只有安装包更新和数据包热更新；**对你是只读** |
| 用户数据 | `%APPDATA%\labreport-writer` | 设置、学生信息、API Key、技能、自建变体、**每个实验的工作副本**（你填的 data.json、改过的 variants.json、生成的报告） | 只有你 |
| 云端 | 腾讯云 COS 桶 + 云函数 | 更新清单、安装包、数据包、贡献与反馈 | 开发者 |

**工作副本机制（ensureUserCopy）**：你第一次对某实验做任何写入（保存数据/保存变体/生成报告）时，软件自动把该实验整个文件夹复制一份到 %APPDATA%，之后所有读写都走这份副本。效果：
- 覆盖重装、卸载重装 → 安装目录被重置，但你的数据在 %APPDATA% 毫发无损；
- 官方发新数据包 → 只更新"出厂层"，合并时你的 data.json **永不覆盖**、你改过的 variants.json 自动保留。

## 第 8 章 更新系统（三种更新，各走各的路）

### 8.1 应用更新（换外壳）
桶根目录的 `latest.json` 是更新清单，**双格式**：

```json
{
  "version": "1.7.5",
  "url": "https://...myqcloud.com/labreport-setup-1.7.5.exe",   ← 老字段：给 1.4~1.6 旧版
  "fileName": "labreport-setup-1.7.5.exe",                        （旧版读到后自动下载→打开安装程序）
  "downloads": [                                                   ← 新字段：给 1.7.x 新版
    { "name": "夸克网盘", "url": "https://pan.quark.cn/s/...", "hint": "提取码 85vN" },
    { "name": "GitHub",  "url": "https://github.com/muhan-ad/xdu-labreport-writer" }
  ]
}
```

新版行为：检查更新 → 只比对版本号 → 有新版本就弹窗展示**两个下载链接**（浏览器打开，用户自行下载）+ 提醒"装到同一位置，否则出现两个版本"。旧版行为：检查 → 自动下载安装包 → 自动打开安装程序。

### 8.2 数据热更新（换内容，不重装）
`data-manifest.json`（数据版本号）+ `data-package-x.zip`（实验脚本树）。点「检查实验数据更新」→ 下载 zip → **安全解压**（防"zip-slip"路径逃逸）→ 按合并规则落进 %APPDATA% 数据根 → 写本地 manifest。以后改变体/知识库/加新实验，只发 0.7MB 的包，用户不用重装 164MB 的安装包。

**云端新增实验**：数据包合并按「目录树」进行，zip 里出现新目录（`实验脚本/<新实验名>/`）即新增实验——管理应用打包推送一次，用户端「检查实验数据更新」后实验列表直接出现新实验，无需重装。数据包 manifest 经 ed25519 签名（`minAppVersion/size/sha256/files/signature` 与用户端验签协议对齐，发布前管理应用用内置公钥自校验）；更新完成后用户端会提示「本次新增实验：xxx」。

### 8.3 数据版本是独立的
应用版本（1.7.5）和数据版本（1.0.0）互不干扰；数据版本由管理端导出时自动 +1（设计约定），你不需要手动改。

## 第 9 章 贡献与反馈（数据回流通道）

用户在实验页点「贡献数据」可上传两类东西，设置里「意见反馈」可提交建议。共同点：**都不经过应用服务器，直接进 COS 的 `contributions/` 目录**。

### 9.1 为什么安全（预签名机制）
应用里**没有任何腾讯云密钥**。上传分两步：

```
① 应用 POST → 云函数：「我要往 contributions/reports/某实验/时间戳/xxx.jpg 传文件」
② 云函数（密钥在它的配置里）校验路径合法 → 算出一个 10 分钟有效的"预签名 PUT 地址"回给应用
③ 应用拿地址直接 PUT 文件到 COS —— 上传流量免费，密钥全程不落地
```

云函数只放行 `contributions/(variants|reports)/<实验>/<时间戳>/<文件>` 和 `contributions/feedbacks/<时间戳>/<文件>` 两种形状，其他一律拒绝。

### 9.2 目录规范（给管理端看的）
```
contributions/
├─ variants/<实验名>/<YYYYMMDD_HHMMSS>/自建变体_<实验名>.json   ← 与 variants.json 同构，可直接导入
├─ reports/<实验名>/<YYYYMMDD_HHMMSS>/
│    ├─ <实验名>-<分数>-<时间戳>_1..9.jpg   （照片，客户端已压到 ~200KB）
│    ├─ <实验名>-<分数>-<时间戳>.docx      （Word 报告）
│    └─ manifest.json  {kind, exp, score, ts, note, appVersion}
└─ feedbacks/<YYYYMMDD_HHMMSS>/feedback.json  {kind:"feedback", text, ts, appVersion, exp}
```

### 9.3 管理端怎么"知道有新货"
不需要谁推送：管理应用打开时列一遍 `contributions/` 的三级目录，和本地"已处理清单"（或桶里 processed/ 归档）对比，**没见过的时间戳目录就是新的**。上传频率再随机也不怕。筛选处理后，管理端把合格内容导出成新数据包 + 自动把 dataVersion +1 传回 COS → 所有用户点一下"检查实验数据更新"就收到。

## 第 11 章 安全设计清单

1. **沙箱隔离**：界面拿不到 Node 能力，一切经 preload 白名单；
2. **路径围栏**：所有写/删操作过 `ensureInside`（拒绝 `..`、绝对越界、zip-slip）；
3. **网络围栏**：更新/上传/外链打开前，URL 必须是 http/https 且域名解析后不含本机/内网/保留地址（防"让软件去访问路由器内网"这类攻击）；
4. **密钥分层**：COS 密钥只在云函数环境变量；API Key 只在本机；应用包里没有秘密；
5. **上传限额与白名单**：单文件 ≤20MB、单次 ≤20 个、路径形状正则校验；
6. **隐私**：学生信息不上传；贡献/反馈需勾选同意条款；报告数据永不覆盖。

## 第 12 章 构建与发布（从代码到用户桌面）

```
npm run build:win
  └─ electron-builder 读取 package.json 的 build 配置：
     ├─ 把 main.js/preload.js/src/ 压进 app.asar（应用代码归档）
```

## 附录 B 常见问题

**Q：换了新电脑/重装系统，数据怎么找回？**
A：设置、学生信息、自建变体、实验数据都在 `%APPDATA%\labreport-writer`——备份这个文件夹即可整体迁移；重装应用后一切自动就位。

**Q：生成报告需要装 Microsoft Word 吗？**
A：**不需要**。报告由本机 Python 直接生成（python-docx + OMML），公式同样是 Word 原生公式。Word 或 WPS 只用于打开检查报告——旧版依赖 Word COM，已因兼容性与稳定性问题于 2026-09 迁移。

**Q：为什么我更新后出现了两个应用？**
A：安装时没装到原位置。卸载多余的，或重装时选择与现有版本相同路径（检查更新弹窗有提醒）。

**Q：贡献上传提示"服务未配置"？**
A：云函数还没部署/地址没填进应用，见 `cloud/contribute-credentials/README.md`。
