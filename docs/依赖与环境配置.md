# 源码依赖与环境配置

## 仓库应包含什么

源码仓库包含依赖声明、Node 锁文件、Python 发布环境版本快照及配置方法，不提交 `node_modules/` 或 Python 解释器二进制。`python-runtime/` 是本地打包资源，不是缺失的源码；维护者自行配置它。安装器中已经包含运行时，普通用户无需另装 Python。

| 项目 | 仓库文件 | 配置方式 |
| --- | --- | --- |
| Node / Electron / 打包工具及全部递归依赖 | package.json、package-lock.json | Node 22.12+，建议 24；运行 npm ci |
| Python 必需包 | requirements.txt → 物理实验/requirements.txt | Python 3.12+，运行 python -m pip install -r requirements.txt |
| 可选 SciPy 插值 | requirements-optional.txt | 按需运行 python -m pip install -r requirements-optional.txt；未安装有多项式回退 |
| 1.7.6 发布运行时包版本 | requirements-runtime-1.7.6.txt、python-runtime-inventory.json | Python 3.14.7 发布环境的版本快照，供同环境重建参考 |
| Microsoft Word 桌面版 | 系统前置条件，不随源码分发 | 安装并完成首次启动；报告通过 Windows COM 生成 |
| 预览、公式和数学排版前端资源 | src 内随源码保存 | 不依赖运行时 CDN 下载 |
| 投稿云函数 | cloud/contribute-credentials | Node 内置模块，零外部 npm 依赖；云端环境变量按该目录 README 配置 |

必需 Python 清单包括代码直接使用的 NumPy、Matplotlib、pywin32，以及已有辅助依赖 openpyxl、python-docx；它们的递归依赖由 pip 安装。开发清单使用最低版本约束，不能视为跨平台完全锁定；发布快照记录了当次环境的精确包版本。

## 本机 Python 配置

在项目根目录执行：

```powershell
npm ci
python -m pip install -r requirements.txt
python -m pip check
python scripts/check-python-dependencies.py
npm run verify
npm start
```

`python` 应指向实际安装的解释器，不能仅有 Windows 商店占位快捷入口。若使用独立环境，要保证应用能找到该解释器；本项目优先识别根目录 `python-runtime/python.exe`。

## 自行配置 python-runtime

维护者在根目录配置 Windows x64 Python，确保 `python-runtime/python.exe` 可执行，包含所需标准库及第三方包，再执行：

```powershell
.\python-runtime\python.exe -m pip install -r requirements.txt
.\python-runtime\python.exe -m pip check
.\python-runtime\python.exe scripts/check-python-dependencies.py
npm run build:win -- --publish never
```

上述 pip 命令以该解释器已配置 pip 为前提。不要只复制虚拟环境中的 python.exe；它可能依赖原机器的基础解释器。Windows 嵌入式发行版还需要正确配置模块搜索路径和 site-packages。

构建配置要求 `python-runtime/` 存在；只有系统 Python 可满足源码运行，不能替代安装包需要携带的目录。是否可在其他电脑运行，仍需实际安装验收。

## 依赖核验

`scripts/check-python-dependencies.py` 扫描实验及 Python 测试的静态 import，检查第三方模块是否有必需/可选依赖声明，并实际导入必需模块。CI 在 Windows 上安装必需包、运行 pip check 和该检查。它不启动 Word，也不替代 Word 的集成测试。
