# 教务课表加密缓存（0.20.0 测试版）

完整同步的课表可按账号保存到本机，重开时读取缓存。恢复缓存始终是“上次课表，请重新同步”，不会据此启用“已核对无冲突”或移除人工核对要求。已有时间重叠仍可用于提醒和拦截，须重新同步核对变化。

## 存储与恢复

文件位于 Android `getNoBackupFilesDir()/academic-cache-v1/<账号 SHA-256>.json`，每个账号一份最新完整课表。内容是明确字段组成的快照，不保存 Cookie、SSO 票据或密码；课程详情与账号均在密文内，文件名不直接包含学号。

使用 AES-256-GCM、随机 IV，AAD 绑定版本和账号；密钥由 Android Keystore 保存，别名 `lab-maker-academic-cache-v1`，与学校账号、AI 配置密钥独立。使用 AtomicFile 写入并回读核对。没有新增运行库或在线存储服务。

部分课表不覆盖上一份完整缓存；恢复时重新检查身份、校历、字段、时间及完整性。篡改、跨账号复制、丢失密钥、异常版本或损坏文件不会成为可用课表，也不自动删除原文件。账号切换只读对应文件；明确清除当前账号时删除对应缓存并清理该账号教务登录，不清除别的账号、筛选偏好、测量数据或报告。

保存失败时保留已经读到的课表并明确提示，可点“重试本机保存”，无需再次请求官网。进入本机写入阶段时显示正在保存，短暂禁用窗口关闭，完成或失败后退出该阶段，避免把已验收数据与取消结果混在一起。离开页面前尚未验收的旧读取仍不能导入。

## 数据规模与提交边界

展开周次后的事件和文字体积均检查上限，在构造整个桥接 JSON 或缓存明文前逐条估算；超过 8 MiB 明确拒绝导入，不截断为“完整课表”。缓存明文、密文和文件读取也有限制。此限制与原始记录/事件数量限制共同控制手机内存占用。

缓存读取可能发生在最终冲突复核中，因此发送边界在读取后再次核对票据有效期和实验是否开始；缓存读取期间跨过边界也不会发送。72 小时取消规则和一次性票据继续保留。

- 72 项原生业务测试通过，新增加密重建实例恢复、账号 AAD 隔离、篡改、错误密钥、损坏文件、失败和部分保存保留旧值、随机 IV、明确单账号清除、缓存不能授予 fresh、展开文字体积限制及最终时间边界。

- 课表生产组件配模拟原生端共 12 项桌面检查通过，含缓存恢复提示、保存失败保留当前数据及不发起官网请求的重试；原有教务筛选/推荐/确认 9 项桌面组件回归通过。
- 六种宽度检查通过；缓存恢复状态的桌面截图已人工检查。Android 原生官网登录窗口及实际磁盘恢复尚未截图验收。
- APK 93 个资源、16 个预期原生类定义、关闭桥参数日志与调试签名核对通过。

核心测试使用 JVM 标准 AES/GCM、注入的测试密钥和内存文件替代器，不能当作真机 Keystore/AtomicFile/重启验收。没有把磁盘缓存恢复视为官网重新认证或重新同步成功。
