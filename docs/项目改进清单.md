# 项目改进清单

> 审查日期：2026-09-14  
> 审查范围：Electron 主进程与界面、Python 报告生成公共库、实验数据校验、数据热更新及项目文档。  
> 当前状态：仅完成只读审查和非写入式验证，尚未实施下列改动。

## 总体结论

项目现有的 26 个实验均通过静态冒烟检查，`main.js`、`preload.js` 和 `src/renderer.js` 也通过 JavaScript 语法检查。当前最需要优先处理的不是实验公式或模板，而是用户数据保护、报告生成结果判定和实验数据热更新流程。

建议先完成 P0 项，再处理 P1 和 P2。每一项实施前均需获得项目所有者确认。

## P0：应优先修复

### 1. 修复实验数据热更新的 `common` 目录复制失败

- **位置**：`main.js` 中的 `copyDir()`、`mergeDataTree()` 和 `apply-data-package`。
- **现状**：处理更新包中的 `common` 目录时，程序先删除用户目录中的旧 `common`，随后用用户数据根目录校验位于临时解压目录中的源路径，路径校验必然失败。
- **影响**：数据更新可能中途失败，并且已经删除用户目录中的公共 Python 库；已有实验随后可能无法生成报告。
- **验证结果**：使用内存中的模拟文件系统复现，程序先执行删除操作，随后报告源路径越界。
- **建议**：分别校验源目录和目标目录；在临时目录中完整校验更新包后，再用可回滚的方式替换公共库。
- **验收标准**：包含 `common` 的合法数据包能够成功更新；非法包不会改变现有文件；复制或校验失败后旧版本仍可正常使用。

### 2. 切换实验前处理未保存的表单数据

- **位置**：`src/renderer.js` 中的 `selectExperiment()`。
- **现状**：编辑数据后点击另一个实验，会直接改变当前实验并加载新表单，同时重置未保存状态。
- **影响**：用户刚填写的数据可能在没有提示的情况下丢失。
- **建议**：检测到当前表单已修改时，显示“保存并切换／放弃修改／取消切换”；切换动作应等待用户选择和保存结果。
- **验收标准**：鼠标切换实验、搜索后选择实验等入口都不能静默丢弃修改。

### 3. 生成报告前统一校验并保存当前表单

- **位置**：`src/renderer.js` 中的 `runGenerate()` 和 `runGenerateReport()`。
- **现状**：生成按钮直接启动 Python；界面中尚未保存的输入不会写入 `data.json`。
- **影响**：界面显示的是新数据，最终报告却可能使用上一次保存的旧数据。
- **建议**：将流程统一为“读取表单 → 完整校验 → 保存成功 → 生成报告”；保存失败或必填项无效时禁止生成。
- **验收标准**：修改任意字段后直接点击生成，报告使用当前界面值；无效数字和缺失必填项会在启动 Word 前被拦截。

### 4. 避免把旧报告误判为本次生成成功

- **位置**：`main.js` 中 `run-generate` 的子进程结束处理。
- **现状**：成功条件是 Python 退出码为 0，且实验目录中存在任意正式 `.docx`。部分实验在数据缺失时只是打印提示并正常返回。如果目录中已有旧报告，应用仍可能显示本次生成成功。
- **影响**：用户可能误以为报告已按新数据更新，实际打开的是旧文件。
- **建议**：生成前记录报告状态；由 Python 明确返回成功、失败和本次产物路径，或验证目标文件确实由本次任务新建或更新。
- **验收标准**：数据缺失、Word 保存失败、目标文件被占用等情况都显示失败；旧报告仍可打开，但不会被当成本次结果。

### 5. 保存数据后同步实验的实际用户数据路径

- **位置**：`main.js` 中 `write-data`，以及 `src/renderer.js` 中 `saveFormData()`。
- **现状**：首次保存会把内置实验复制到用户数据目录，并返回新路径，但界面没有更新 `currentExp.path` 和实验列表中的对应路径。
- **影响**：保存后切换到其他实验再切回来，可能重新读取内置示例数据，直到下一次完整扫描实验列表。
- **建议**：保存成功后立即同步当前实验和列表项的路径，或让主进程只接收实验 ID 并统一解析真实数据目录。
- **验收标准**：首次保存后反复切换实验，始终读取用户刚保存的数据。

### 6. 将 AI 润色结果绑定到来源实验

- **位置**：`src/renderer.js` 中 `runAiPolish()`、`renderAiResults()` 和 `importPolishAndRegenerate()`。
- **现状**：润色结果只记录章节和文本；导入时使用当时的 `currentExp.id`。
- **影响**：AI 请求期间或完成后切换实验，可能把实验 A 的文字导入实验 B。
- **建议**：每次润色任务记录实验 ID、章节、原文版本和请求 ID；导入前再次核对当前实验和源版本。
- **验收标准**：切换实验不会造成跨实验导入；过期结果会明确提示重新润色。

### 7. 精确识别并清理自动化创建的 Word 进程

- **位置**：`main.js` 中 `cancel-generate`，以及 `物理实验/实验脚本/common/docx_report.py`。
- **现状**：取消生成时通过“生成前不存在、生成后存在”的 PID 差集清理 Word。
- **影响**：用户若在生成期间手动启动 Word，该进程也可能被识别为本次生成产生并被结束。
- **建议**：从 Word 自动化对象获取实际进程 ID，或为每次任务建立可追踪的进程归属，不使用全局进程差集作为最终依据。
- **验收标准**：取消生成只结束该任务创建的 Word；用户此前或期间手动打开的 Word 均不受影响。

## P1：重要改善

### 8. 建立安装升级后的用户数据迁移机制

- **位置**：`main.js` 中 `ensureUserCopy()`。
- **现状**：路径已经位于用户数据目录时会提前返回，安装新版后不会同步新版 `generate.py`、schema、知识库和公共库。
- **影响**：曾经使用过的实验可能长期运行旧代码，而未使用过的实验运行新代码，造成版本不一致。
- **建议**：给内置资源添加版本清单；升级时更新程序资源，只保留用户拥有的数据文件、报告和自建内容。
- **验收标准**：应用升级后，所有实验使用同一版本的程序资源，用户填写的数据与自建变体保持不变。

### 9. 完善 schema 数据校验

- **位置**：`validate_schema.py` 和界面的 `refreshFormCheck()`。
- **现状**：矩阵为错误的一维结构时，必填检查可能直接抛出异常；`NaN` 和无穷大也会被当作合法数字。界面只检查必填项，没有完整复用 Python 校验规则。
- **影响**：异常数据可能绕过界面，或令检查工具崩溃。
- **建议**：先检查容器结构，再遍历内容；拒绝非有限数值；让主进程和命令行共享同一份可测试的校验约定。
- **验收标准**：任何格式错误都返回结构化错误，不抛出未处理异常；界面与命令行给出一致结果。

### 10. 让自动检查在发现问题时返回失败状态

- **位置**：`smoke_test.py` 和 `package.json`。
- **现状**：冒烟脚本即使发现异常，也没有以非零状态退出；项目也没有统一的检查命令。
- **影响**：持续集成或发布脚本可能把失败结果当作通过。
- **建议**：异常时返回非零退出码；增加统一检查入口，并覆盖保存→生成、热更新、旧报告判定和异常 schema。
- **验收标准**：制造一个受控错误时检查命令失败；恢复后全部通过。

### 11. 收紧主进程文件访问边界

- **位置**：`main.js` 中接收 `expPath` 或 `filePath` 的 IPC 接口。
- **现状**：部分读取、打开和生成接口直接使用界面传入的绝对路径，限制不一致。
- **影响**：一旦界面内容或第三方库被利用，主进程提供的文件能力会扩大影响范围。
- **建议**：界面只传实验 ID 或报告 ID；主进程从允许的内置目录和用户数据目录解析真实路径，并统一执行边界与扩展名检查。
- **验收标准**：合法实验和报告正常工作；工作目录之外的路径、软链接越界和不允许的文件类型均被拒绝。

### 12. 改善 API Key 的本地存储

- **位置**：`src/renderer.js` 中应用设置的读写。
- **现状**：API Key 与普通设置一起保存在 Electron `localStorage`。
- **影响**：同一用户权限下，能够读取应用数据目录的程序可直接获得明文密钥。
- **建议**：使用操作系统提供的安全存储能力；界面只显示掩码，不把密钥返回给普通渲染逻辑。
- **验收标准**：应用数据文件中不出现明文 Key；已有用户的密钥能够安全迁移或明确重新录入。

## P2：维护性与体验

### 13. 拆分主进程和界面脚本

- **位置**：`main.js` 约 1,625 行，`src/renderer.js` 约 2,785 行。
- **现状**：扫描、更新、文件管理、AI、贡献上传、表单、队列和弹窗状态集中在两个文件中，共享多个全局变量。
- **影响**：功能之间容易互相覆盖状态，修改和测试成本较高。
- **建议**：按实验仓库、生成任务、数据更新、AI、报告管理和界面状态拆分；先提取纯函数和状态边界，再逐步迁移。
- **验收标准**：用户行为保持一致，关键模块可以单独测试，异步结果不会覆盖已经切换的页面。

### 14. 清理重复事件监听器

- **位置**：数据更新进度、生成日志等事件注册位置。
- **现状**：部分监听器在每次操作时追加，预加载接口没有提供取消订阅方法。
- **影响**：多次检查更新后，同一进度事件可能触发多个旧回调，形成内存占用和界面状态串扰。
- **建议**：预加载接口返回取消订阅函数；对单例事件只注册一次，并由当前任务状态消费。
- **验收标准**：连续执行多次更新或生成后，每条事件只处理一次。

### 15. 同步 README 与当前实现

- **位置**：`README.md`。
- **现状**：文档仍写“应用内使用说明未开发”“发现新版本后自动下载”“19/26 实验已有变体”等内容，与当前代码或资源不一致。
- **影响**：开发者和用户会对实际能力、数据目录和更新方式产生误解。
- **建议**：以当前行为为准更新功能说明、资源数量、用户数据目录和更新流程。
- **验收标准**：README、应用内说明和实际界面行为一致。

### 16. 增加完整的运行验证清单

- **建议覆盖**：
  1. 首次保存后切换实验并重新读取；
  2. 未保存数据直接生成；
  3. 数据缺失且存在旧报告；
  4. 目标报告被 Word 占用；
  5. 生成期间切换实验并导入 AI 结果；
  6. 取消生成且同时手动打开 Word；
  7. 合法、损坏、越界和中途失败的数据更新包；
  8. 安装新版本后保留用户数据并更新程序资源。

## 已完成的只读验证

- 26 个实验通过当前 `smoke_test.py` 静态检查，异常数为 0。
- `main.js`、`preload.js`、`src/renderer.js` 通过语法检查。
- 热更新 `common` 目录问题通过内存模拟复现，没有改写项目或用户数据。
- schema 校验器对畸形矩阵直接抛出异常的问题已通过独立输入复现。
- 未启动 Electron 应用、Microsoft Word、真实 AI 请求或真实远端更新，因此这些运行链路仍需在修复后验证。

## 建议实施顺序

1. 热更新安全与回滚（第 1 项）。
2. 未保存数据保护、生成前保存、真实成功判定（第 2～5 项）。
3. AI 结果归属和 Word 进程归属（第 6～7 项）。
4. 资源版本迁移、校验与自动检查（第 8～10 项）。
5. 安全边界、密钥存储、模块拆分和文档同步（第 11～16 项）。

实施任何一项前，应先确认具体编号和允许修改的文件范围。
