# 安卓更新验签兼容与资源中断补验

0.76.0（79）修复了当前 Android System WebView 未提供 Ed25519 原生接口时，应用更新和实验数据更新的合法清单均无法验证的问题。不是取消验签，也没有改变内置发布公钥。

原生 `importKey` / `generateKey` 实测返回 `NotSupportedError`，原先只在桌面 Chrome 的签名测试没有覆盖此差异。新增公共验证器优先使用系统实现；仅不支持算法时按需加载本机随包提供的 `@noble/ed25519` 3.2.0，使用严格模式验证。固定 Ed25519 SPKI 格式与签名长度，原生验证返回 false 或其他异常不会转为通过。来源、版本、大小、摘要和包身份检查保留。MIT 许可已随安装包附带。

兼容实现仍依赖 WebCrypto SHA-512，不宣称适用于完全缺少 WebCrypto 的环境。库接口及严格模式依据上游文档：https://github.com/paulmillr/noble-ed25519 。没有从远程加载可执行代码。

## 当前证据

- 全部 346 项领域测试、TypeScript、完整 Android 构建/单元测试、资源/原生类/签名检查通过。新增验证包括 RFC8032 独立向量、篡改正文与签名、另一公钥、损坏 DER、非规范标量、小阶公钥、原生拒绝以及其他异常不放行；两种更新协议共用兼容验证器。
- 现有浏览器签名 3 项、应用更新界面 9 项回归通过。
- 独立 Android 验收包 7 项通过：真实 WebView 合法及篡改清单验证，真实 Filesystem 的双包保存/回读及 28 实验生产 Worker 预检，在第一份版本保护及第一份活动指针写成后终止测试进程并重开，同包重试，双份损坏后的上一份回退，恢复内置后的版本保护保留。
- 原生报告 Worker 使用恢复后的资源生成 46,124 字节 DOCX、64 个公式；模板与知识标记一致，实际 Word XML 文本也含 V2 标记。
- 0.76.0 安装包实际界面的补验另确认：当前 WebView 仍缺少原生 Ed25519，而文件导入已能进入“发布签名验证失败”的严格拒绝，错误发布者未获得启用入口。该检查使用测试 DOM 提供合成文件，不冒充系统文件选择器验收。
- APK 内验证模块及许可证已核对。与 0.75.0 相比，完整安装包增加 5,592 字节。当前模拟器主包已备份更新，215 份原数据/配置摘要全部一致。

结果：`artifacts/verification/native-data-update-1793142474381/`、`native-knowledge-policy-1793142458361/`、`delivery-0.76.0/preservation.json`；原始失败及修复前测试日志保留。
